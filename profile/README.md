<p>资源分配做不好，通常不是买少了，而是没人说得清「这条出口属于谁、这个并发额度归哪个项目、这个人还能不能改配置」。与其靠口头约定，不如写一份参数说明书：把项目、账号、成员、出口四类对象各自的参数、默认值和调整规则定下来，谁要动就按规则走。下面这份可以直接改成你团队的内部文档，参数默认值按常见规模给出，可按实际体量等比调整。</p>

<h2>说明书覆盖什么：四类对象与一张总表</h2>
<p>分配的本质是把有限资源切成互不重叠的份额，并且让份额可追溯到人。四类对象里，项目是预算单位，账号是身份单位，成员是操作单位，出口是网络单位。四者不是层级关系，而是四个正交维度，任何一个请求都应该能同时定位到这四项。</p>
<p>落地时只需一张总表，每行一个账号，列出所属项目、绑定出口编号、负责人、并发额度、日志可见范围。这张表是唯一事实来源，配置改动先改表再改系统。</p>

<h2>维度一 项目：先切预算，再切资源</h2>
<p>顺序不能反。先给项目定月度额度（金额或流量），再按额度倒推能买几条出口、多少并发。若先买资源再分摊成本，很容易出现某项目占了七成带宽却只付两成预算的情况，年底算账时无从解释。</p>
<p>额度口径建议统一成「折算金额」，即带宽费、IP 月费、超量流量费、替换费全部折成钱，而不是各自记各自的数量。口径统一后，跨项目的横向比较才有意义。</p>

<h3>额度给多少合适</h3>
<p>新项目按预估用量的 1.3 倍起步，跑满两个月后再校准；稳定项目按过去三个月峰值的 1.15 倍定。上浮太多会让预算虚高，太少则频繁触发超量计费，两者都不经济。</p>

<h3>跨项目共用的处理</h3>
<p>确实需要共用时，指定一个「主责项目」承担费用，其他项目按实际用量内部结算，并在总表里标注共用关系。最忌讳的是共用但没人认账，出问题时互相推。</p>

<h2>维度二 账号：一号一出口是默认值</h2>
<p>把「一个账号绑定一条出口」写成默认规则，例外必须写理由并留审批记录。这样做不是为了教条，而是因为一旦允许随意共用，后续排查「某账号为什么出现异常提示」时，无法排除同出口其他账号的行为干扰。</p>
<p>绑定关系要写进总表，并附上绑定日期。历史上出现过同一账号在不同时间被绑到不同地区的情况，导致登录记录里地区来回跳，这类记录在有表可查时几分钟就能说清。</p>

<h3>允许的例外有哪几种</h3>
<p>常见的合理例外：同一项目的多个只读账号共用一个出口；测试环境的多账号共用一条低配出口；临时活动期间短期共用。三类都要标注起止日期，到期自动回收，避免临时方案变成长期事实。</p>

<h3>并发额度怎么落到账号上</h3>
<p>并发额度按项目分配，再在项目内按账号二次分配。若无法精确到账号，至少按分组设上限，防止单个账号的脚本失控把整组额度吃满。额度用尽时建议排队而不是直接拒绝，体验差异很大。</p>

<h2>维度三 成员：三档权限与一套交接动作</h2>
<p>权限分三档就够：只读（看用量与日志）、运维（可改代理配置与重启连接）、管理（可分配额度与增删成员）。多数人只需要只读或运维，管理权限控制在两三人以内。</p>
<p>交接是容易出事的一环。成员离职或转岗时，要同时完成四件事：收回账号登录权限、改掉其掌握的代理口令、把其名下账号转移给新负责人、检查其是否有本地保存的配置副本。前两步常被记住，后两步最容易漏。</p>

<h3>日志可见范围也要授权</h3>
<p>日志里包含访问目标与时间，属于敏感信息。建议按项目授权，成员只能看到自己负责项目的日志，跨项目查看需要管理权限。这样既满足排障需要，也避免无关人员看到不该看的内容。</p>

<h3>为什么要留一份「谁改了什么」</h3>
<p>参数说明书的效力来自可追溯。每次调整额度、更换出口、变更成员权限，都在总表的变更列里留一行：时间、操作人、原因。三个月后回看，这一列能省掉大量争论。</p>

<h2>常见问答</h2>
<h3>总表用什么工具维护比较好？</h3>
<p>答：在线表格就够，关键是权限可控、有变更记录。若团队已有工单系统，把变更走工单、表格只反映当前状态会更规范，但小团队直接用表格加变更列也能跑起来。</p>
<h3>账号多到几十个，还适合一号一出口吗？</h3>
<p>答：适合的场景仍占多数，但可以按分组批量绑定，一组对应一条出口，牺牲部分隔离度换取管理成本下降。若账号之间存在明确的业务隔离要求，仍建议一对一。</p>
<h3>并发额度按账号分，会不会浪费？</h3>
<p>答：会有一定闲置，但比失控好。折中做法是按项目设硬上限、按账号设软上限，软上限被突破时告警而不阻断，观察一段时间后再决定是否调高。</p>
<h3>成员离职后最容易被忽略的一步是什么？</h3>
<p>答：本地保存的配置副本。口令改了但配置文件还在个人电脑里，等于没改。交接清单里应包含「确认个人设备上相关配置已删除」这一项。</p>

<h2>合规提示</h2>
<p>资源分配制度的目的在于可追溯与成本可控，实施时应确保账号来源合法、使用范围符合目标服务条款与当地法规。本文不提供任何多账号规避平台规则的操作方法。</p>
<p>文中默认值与调整幅度为经验建议，需结合团队实际规模调整，仅供参考。</p>
